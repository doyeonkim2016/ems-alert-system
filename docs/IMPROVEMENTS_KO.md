# 다음 개선점

2026-11-22 기준입니다. 위에 있을수록 실제 운영에 쓸 수 있는지를 더 크게 좌우합니다.

## 1. 알림 피로도 관리 (가장 중요)

- **상태 관리:** 지금은 같은 알림이 매일 다시 옵니다. FACTOR 같은 설정 문제는 고칠 때까지 매일 "Still open"으로 나갑니다. 알림에 **Acknowledge / 기간 지정 Snooze / Resolved** 상태가 필요합니다.
- **일일 메시지:** "새로 생긴 것 + 상태가 바뀐 것"만 보내야 합니다.
- **상위·하위 중복 묶기:** Jakarta 컴프레서 누수가 Grid incomer 이상으로도 같이 뜹니다. `hierarchy_path`로 상위·하위 관계를 묶고, 하위 미터 이상으로 설명되는 상위 미터 알림은 접습니다.

## 2. 이상 탐지의 우선순위와 신뢰도

- **심각도 기준:** 지금은 z값으로만 판단합니다. 운영자가 보고 싶은 건 "평소보다 몇 kWh 더 썼나"입니다. 초과 사용량(실제 − baseline)을 합산해 심각도와 정렬 기준으로 쓰면, 누수처럼 돈이 새는 건이 위로 올라옵니다.
- **baseline의 한계:** baseline이 "같은 요일, 최근 3주"뿐이라 공휴일, 생산계획 변경, 정비 주간에 오탐이 날 수 있습니다. 생산 캘린더나 운영일 정보를 반영해야 합니다.
- **ML 확장:** 이후 Isolation Forest 같은 모델로 넓힐 때는 같은 finding 구조에 룰 종류만 추가합니다.

## 3. 시간 기준

- **UTC 날짜 vs 공장 현지 운영일:** Jakarta는 UTC 하루가 현지 생산일 두 개에 걸칩니다. 월간 합계가 공장 보고서와 맞지 않을 수 있습니다.
- **`legacy_direct_delta` → `vee_v1` 경계 (2026-07-01):** 12개월 뷰가 이 날짜를 가로지르는데 화면에 표시가 없습니다. 전후 수치를 같은 기준으로 비교하는 것처럼 보이므로 차트에 방법론 변경선을 넣어야 합니다.

## 4. 스키마에 아직 없는 운영 정보 (실제 구현 전에 정의 필요)

- 태그별 승인된 cadence. 지금은 `expected_rows`를 96으로 가정했습니다.
- 공장 시간대와 위치. 지도 좌표는 현재 임시 목록입니다.
- 공장별 알림 수신 채널.
- 룰 버전 변경 이력. 임계값을 바꾸면 과거 알림이 어느 버전으로 생성됐는지 남아야 합니다.
- Bronze 파싱 실패(quarantine) 건수. NO_READING이 원천 누락인지 파싱 실패인지 구분하려면 필요합니다.

## 5. 규모와 사용성 (미터 약 1,000개 기준)

- **미터 찾기:** Plant meters에 미터 검색과 계층 접기·펼치기가 필요합니다.
- **색만으로 구분되는 화면:** 월간 그리드와 히트맵은 색으로만 상태를 구분합니다. 색각 이상 사용자를 위해 패턴이나 아이콘을 보조로 넣습니다.
- **안 쓰는 데이터:** `selected_tag_hourly`가 아직 화면에 없습니다. 15분과 월 사이에 시간별 패턴 뷰가 있으면 좋습니다.
- **데이터 로딩:** 지금은 모든 데이터를 브라우저에서 만들고 계산합니다. 실제 앱은 앱 DB에서 집계 테이블을 읽고 페이지 단위로 불러와야 합니다.
- **접근 제어:** 공장별 접근 제어(EMS Atlas 리뷰 H4)는 실사용 전에 다시 넣어야 합니다.
